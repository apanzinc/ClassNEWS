# ClassNEWS 插件系统逻辑说明

## 一、架构设计

### 1.1 插件分类

| 类型 | 位置 | 权限 | 用途 |
|------|------|------|------|
| **内置插件** | 软件内部（打包进 exe） | 只能禁用，不能卸载 | 官方新闻源，必须存在 |
| **用户插件** | %APPDATA%/ClassNEWS/plugins/ | 可禁用，可卸载 | 用户自行安装 |

### 1.2 目录结构

```
ClassNEWS/                          # 软件目录
├── plugins/                        # 内置插件目录（打包进 exe）
│   ├── builtin_official/           # 官方新闻插件（ID: 1）
│   │   ├── plugin.py
│   │   └── config.json
│   └── template/                   # 开发模板
│       └── plugin.py
└── ...

%APPDATA%/ClassNEWS/                # 用户数据目录
├── plugins/                        # 用户插件目录
│   ├── plugin_states.json          # 插件启用状态持久化
│   └── [用户安装的插件]/
│       └── plugin.py
└── ...
```

## 二、核心逻辑

### 2.1 插件加载流程

```
软件启动
    │
    ▼
PluginManager 初始化
    │
    ├── 确定内置插件目录（软件内部）
    ├── 确定用户插件目录（%APPDATA%）
    └── 加载 plugin_states.json（上次的状态）
    │
    ▼
加载内置插件（builtin_dir）
    │
    ├── 遍历 plugins/ 下的每个子目录
    ├── 检查 plugin.py 是否存在
    ├── 动态导入模块
    ├── 实例化插件类
    └── 注册到内存
    │
    ▼
加载用户插件（user_dir）
    │
    └── 同上流程
    │
    ▼
应用持久化状态
    │
    └── 根据 plugin_states.json 设置启用/禁用
```

### 2.2 插件接口（INewsSource）

所有插件必须实现以下方法：

```python
class INewsSource(ABC):
    @abstractmethod
    async def fetch_news(category, count, cursor) -> FetchResult:
        """获取新闻列表"""
        pass
    
    @abstractmethod
    async def get_news_detail(news_id) -> NewsItem:
        """获取新闻详情"""
        pass
    
    @abstractmethod
    async def play_news(news_id) -> bool:
        """播放新闻（语音播报）"""
        pass
    
    async def search_news(keyword, count) -> List[NewsItem]:
        """搜索新闻（可选实现）"""
        pass
```

### 2.3 安全性设计

1. **进程内通信**：插件和主软件在同一个 Python 进程内，通过内存方法调用，不走 HTTP
2. **异常隔离**：单个插件加载/运行失败不影响其他插件和主程序
3. **内置插件保护**：内置插件目录只读，用户无法删除
4. **用户插件沙盒**：用户插件只能访问自己的目录

### 3.2 PluginManager 方法

```python
# 加载

# 查询

```

## 五、打包注意事项

### 5.1 内置插件打包

`build_exe.py` 中必须包含：

```python
datas=[
    ...
    ('plugins', 'plugins'),  # 内置插件目录
],
```

### 5.2 用户插件目录

打包后运行时自动创建：
- Windows: `%APPDATA%\ClassNEWS\plugins\`
- macOS: `~/Library/Application Support/ClassNEWS/plugins/`
- Linux: `~/.classnews/plugins/`

## 六、常见问题

### Q1: 插件加载失败怎么办？

检查：
1. plugin.py 是否存在
2. 是否导出 `plugin_class`
3. 类是否继承 `INewsSource`
4. ID 是否冲突

### Q2: 如何调试插件？

```python
# 在 plugin.py 中添加日志
import logging
logger = logging.getLogger(__name__)
logger.info("插件加载成功")
```

### Q3: 内置插件和用户插件冲突？

内置插件先加载，用户插件后加载。如果 ID 冲突，用户插件会加载失败。

### Q4: 插件不兼容怎么办？

UI 会显示"不兼容"标签，但插件仍可加载使用。如需使用，请更新插件的 `api_version` 字段或等待插件作者更新。

## 七、QML API 参考

### PluginManager 属性

| 属性 | 类型 | 说明 |
|------|------|------|
| `plugins` | list | 插件列表，每项包含: pluginId, name, type, enabled, builtin, author, version, description, apiVersion, compatible |

### PluginManager 方法

```qml
// 启用/禁用插件
pluginManager.setPluginEnabled(pluginId, enabled)

// 卸载插件（用户插件）
pluginManager.uninstallPlugin(pluginId)

// 导入插件（打开文件对话框）
var conflicts = pluginManager.importPlugin()

// 导出插件（保存为 .cnplugin）
var path = pluginManager.exportPlugin(pluginId)

// 重载插件（用户插件热更新）
pluginManager.reloadPlugin(pluginId)

// 打开插件目录
pluginManager.openPluginFolder(pluginId)

// 获取 API 版本
var version = pluginManager.getAPIVersion()

// 检查兼容性
var ok = pluginManager.isPluginCompatible(pluginId)
```

### PluginManager 信号

| 信号 | 参数 | 说明 |
|------|------|------|
| `pluginListChanged` | - | 列表变化 |
| `pluginImportSucceeded` | - | 导入成功 |
| `pluginImportFailed` | msg | 导入失败 |
| `pluginReloadSucceeded` | pluginId | 重载成功 |
| `pluginReloadFailed` | pluginId, msg | 重载失败 |
| `pluginExportSucceeded` | filePath | 导出成功 |

## 八、cwplugin.json 格式

```json
{
    "id": 1001,
    "name": "我的新闻源",
    "version": "1.0.0",
    "api_version": "1.0.0",
    "author": "作者名",
    "description": "插件描述",
    "compatible": true
```

| 字段 | 必填 | 说明 |
|------|------|------|
| id | ✅ | 插件唯一 ID |
| name | ✅ | 插件名称 |
| version | ✅ | 版本号 |
| api_version | ✅ | 要求的 API 版本 |
| author | ✅ | 作者 |
| description | ❌ | 描述 |
| compatible | ❌ | 兼容性标记 |
